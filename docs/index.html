Claude Code plugin · Laravel 13 · PHP 8.4

laravel-production-audit

Point Claude at an existing Laravel app and get back a severity-rated readiness report — every finding cites file:line — plus a folder of ready-to-drop-in production config files.

Install View on GitHub

What it does

Reads the actual code and config first, then prescribes — never guesses at defaults.

Request lifecycle

Flags blocking work in the request path — sync HTTP calls, un-queued mail, heavy middleware.

Queue & Horizon

Job design, supervisor sizing, failed-job handling, and orphaned queues nothing drains.

Memory & footprint

Unbounded loads, chunking, per-worker RSS — built for small hardware.

Database

N+1 detection, missing indexes, query efficiency, and write-in-loop patterns.

Redis

Cache / session / lock usage, TTL gaps, phpredis vs predis, DB separation.

Server config

PHP-FPM pool, OPcache (PHP 8.4 JIT), Supervisor, and a hardened Nginx block.

Concurrency

Duplicate jobs, TOCTOU races, and atomic-lock patterns under load.

Multi-tenancy

Per-tenant cache and queue isolation — where a missing prefix is a data leak.

Install

In Claude Code — add the marketplace, then install the plugin.

# Claude Code (slash commands) /plugin marketplace add corbital/corbital-laravel-plugins /plugin install laravel-production-audit@corbital-laravel-plugins
# …or the CLI equivalent claude plugin marketplace add corbital/corbital-laravel-plugins claude plugin install laravel-production-audit@corbital-laravel-plugins

Then just ask in plain language — the skill auto-triggers. Or invoke it explicitly with /laravel-production-audit:laravel-production-audit.

Then ask

No flags, no path syntax — natural language pulls the skill in.

“Audit my Laravel app for production readiness and give me the config files.”

“Why is my Laravel app slow under load?”

“Tune Horizon — workers keep getting OOM-killed.”

“Get this Laravel project production-ready before we go live.”

What you get back

Two deliverables, written into the project you audited.

PERF_AUDIT_REPORT.md

Findings grouped by severity, each citing a real file:line, plus a section-by-section breakdown.

🔴 Critical 🟠 High 🟡 Medium ✅ OK

PERF_CONFIGS/

Complete, production-ready files — populated from the findings:

  • horizon.php, supervisor-laravel.conf
  • php-fpm-www.conf, opcache.ini, php-web/cli.ini
  • nginx-performance.conf, redis-separation.md
  • .env.production.example, deploy-cache.sh, INDEXES_TO_ADD.md

How it's built

Progressive disclosure — a lean core that loads detail only when needed.

Self-contained sections

11 audit sections, each its own reference file with its own checklist and severities. Run the whole thing — or just one section.

Reusable templates

Every config file is a standalone annotated template. Grab opcache.ini on its own, no audit required.

Honest by design

Every finding ties to code it read. Severity rates by impact, never by how hard the fix is.
